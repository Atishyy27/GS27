## 1. What GS27 is today, in plain words

A Next.js 16 + Supabase app in `apps/web`. A student signs in with Google (or enters as a guest, read only), picks a college,
branch and batch, and uses: a library of subjects shared across colleges (files, votes, reports), a feed, groups, moderation,
a Hall of Fame, a T&P console and a recruiter side. The home page is a MapLibre campus map (`src/app/page.tsx`).
There are no placement statistics in it (his instruction of 16 Oct); this plan keeps it that way.
GS27 has never been live on its own: `apps/web/SETUP.md` ("going live") is still undone, and there is no analytics library
in `apps/web/package.json`.

His own direction (PLAN.md, 17 Nov): the product is academic sourcing. Type a subject code, get every paper, note, the
syllabus and the exam date. Everything else hangs off the subject page.

## 3. Findings, ranked

F1. `pnpm build` stops with `SecurityFatalError`, but it is an agent reminder, not a compile failure.
`node_modules/next/dist/lib/upgrade/nudge.js` throws it when a coding agent runs `next build` on a version that has a known
advisory; the message says "Retry the same command to continue". The docs say the same
(`dist/docs/01-app/03-api-reference/05-config/01-next-config-js/agentUpgrade.md`: "the first eligible reminder stops the
command ... Retrying the same command promptly continues the original task with a warning").
The 18-19 Nov log shows compile and TypeScript passing before the error; nobody retried.
For a caller that is not an agent the build path returns before any stop (`nudge.js`: `if (!signal || signal.aborted) return;`
when no agent is detected), so a human terminal, CI and Vercel are not stopped by it. That also means the two failed
Vercel preview builds have some other cause, still unknown. The real issue is underneath:
Next 16.4.0 is affected by the 3 Nov 2026 release (seven advisories, patched in 16.4.5; npm `latest` is 16.4.6).
Does it reach GS27 code? No Cache Components (`next.config.ts` has none), no `use cache`, no Edge routes, no `next/image`
(grep of `src`), and Vercel hosts it, so the self-hosted advisories do not apply. Real exposure is probably nil;
the upgrade is still the documented fix, and it is what silences the reminder.
Unknown: why the two Vercel preview builds failed (logs need `vercel inspect`, which this run may not use).

F2. The unapplied `0012_pyq.sql` lets any signed-in student overwrite a published solution.
`0012_pyq.sql:86` is `create policy "solutions add" ... with check (public.is_onboarded())`. It does not pin `status` or
`author_id`. `status` defaults to `published` and `PastQuestions.tsx:35` shows the highest published version. So any
onboarded student can insert version 99 as published and replace the canonical answer. His own rule (PLAN.md Scope v2):
vandalism by override is P0. The same pattern is on papers, questions and links (`0012_pyq.sql:71,76,81`), and
`papers.college_id` is free text from the client, so a bad row can also dodge `is_mod_of`. Because 0012 was never applied
(no Supabase work has been done), it can be fixed in the file before it is ever committed.

F3. The past-questions work is 6 uncommitted files in the primary checkout, sitting since 18-19 Nov
(`PLAN.md`, `library/s/[id]/page.tsx`, `PastQuestions.tsx`, `0012_pyq.sql`, `0013_seed_me46018.sql`, `plans/`).
The generator that produced 0013, `cnc/college/placecom-data/gen_pyq_seed.py`, is not in any git repo: `cnc/.gitignore:5`
is `*` (whitelist) and `git ls-files` returns nothing for it. That breaks his "no code only on this laptop" rule.

F4. The library is nearly empty outside first-year Mechanical. 11 subjects of about 400 (section 2). A CSE sem-5 student
lands on `[sem]/page.tsx:91` "No subjects listed here yet. Add the first one below." A guest sees only "Sign in to add"
(lines 104-105), so a dead end.

F5. The USP has no entry point. The home page is only the map (`page.tsx:1-9`), the nav has five links and no search
(`Nav.tsx:10-16`). Type-a-code is his 17 Nov USP. Fixing it before F4 is useless: search over 11 subjects returns nothing for
most branches. So it follows the syllabus seeding; it is not one of the top changes in this run.

F6. Solutions render as plain text with raw LaTeX (`PastQuestions.tsx:52`, `whitespace-pre-line`). Known (phase 2 in his
plan). Not in this run.

F7. No test runner and no CI. `package.json` has only dev, build, start, lint. Nothing proves any change except a local
build, which is the thing that is blocked and which the hard rules say not to run locally.

F8. Subject names are unique across the whole app (`0006_colleges.sql:122`, `unique index on lower(name)`). Good for
sharing notes; for per-branch syllabus it means "Mathematics III" is one subject for all branches, so syllabus text must be
